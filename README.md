## Cogito 是什么

Cogito 是一个**本地运行**的 AI 知识探索工作区，帮你把「零散的念头」和「读不懂的长文档」变成**一棵可回溯、可编辑、可继续生长的知识树**。

它用「卡片」作为知识的最小单元：一次 AI 生成，不是吐给你一大段回答，而是产出一张**有标题、有正文、有术语定义、可单独编辑和推翻**的卡片。卡片之间通过 深入 / 发散 / 分支 三种关系长成树，这张树既可以用卡片列表阅读，也可以一键切换成思维导图纵览全貌。

它不接云、不注册账号、不上传你的任何资料——数据和 API Key 全程只存在于你自己的电脑里。

> **一句话定位**：Cogito 不是「你问它答」的聊天机器人，而是「你定方向、它帮你展开」的个人知识生长系统。

## 痛点：你现在的 AI 用法，卡在哪里

### 痛点一：问完即弃，知识无法沉淀

主流 AI 工具按「对话」组织内容：一条对话一个主题，关掉窗口，思考的产物就蒸发在历史记录里。下周想接着上次的思路继续，只能往前翻聊天记录，翻到了也是一整墙的流水账。

> **后果**：你花在写作、思考、阅读上的时间，没有变成任何可复用的资产。

### 痛点二：思考的主动权，在不知不觉中被 AI 夺走

这是最隐蔽的问题。你提一个问题，AI 直接给一个完整答案——**你是被答案牵引，而不是被自己的问题驱动**。它替你做了选题、定了结构、给了结论，你只剩下「接受或不接受」。长期如此，你的提问能力、判断能力、发散能力都在退化。

> **后果**：你以为在用 AI 思考，其实是 AI 在替你思考。你变成了「审稿人」，而不是「作者」。

### 痛点三：AI 黑话挡路，越学越挫败

CoT、RAG、上下文窗口、Token、前缀缓存……AI 的回答里到处是术语，没人解释，查一个引出一堆。**尤其对于初学者**，这不是工具问题，是生态的门槛问题。

> **后果**：学习曲线陡峭，读不懂→不想读→放弃，宽度和深度都被卡住。

### 痛点四：长文档啃不动，读完即忘

拿到一篇 30 页的 PDF，通读一遍要一小时，划重点费精力，合上文件什么也不记得。摘要工具给你一段话，但那段话**不是你自己的思考结构**，你没法基于它继续生长。

> **后果**：文献、论文、报告这些高价值资料，投入产出比极低。

### 痛点五：灵感碎片散落各地，形不成体系

备忘录、收藏夹、聊天记录、草稿箱……你的灵感碎片散落在七八个地方，没有一个地方能告诉你：**我到底思考过什么？这些问题之间是什么关系？**

> **后果**：感觉每天都在输入，但永远没有「自己的框架」。

### 痛点六：AI 输出不可信、不可控、不可溯源

它用了哪个模型？花了多少 Token？为什么这次回答和上次不一样？失败了是网络问题还是模型抽风？主流工具把这些都藏起来——你既无法追溯，也无法局部修改，改一句话常常要重新生成整段。

> **后果**：AI 输出质量不稳定时，你只能整段重来，成本失控且不知道怎么改。

### 痛点七：隐私没有保障

云端工具意味着你的文档、你的思考过程、你的 API Key 都要经过别人的服务器。对企业资料、个人研究、未发表的写作来说，这条红线挡住了很多本可用 AI 的场景。

> **后果**：要么冒着风险上传，要么干脆不用。

### 痛点八：环境搭建门槛，劝退非开发者

想深入用 AI 工具的人里，很大一部分不是开发者。「装 Node、配环境变量、开两个终端、处理端口冲突」这串前置条件，对会写代码的人只是一分钟的事，对其他人是一堵墙——很多本可受惠于 AI 的人，停在了「怎么把它跑起来」这一步。

> **后果**：好用的工具只属于懂技术的人，工具本身变成了一种筛选器。

| 维度 | 主流 AI 问答工具 | Cogito |
|---|---|---|
| 产出形态 | 一次性对话流 | 可生长的卡片知识树 |

| 导图与笔记 | 两套工具不同步 | 同一份数据的两种视图 |

## 设计哲学：你思，它拓

「Cogito」取自笛卡尔的 *Cogito, ergo sum*（我思故我在）。这个名字想提醒的正是核心主张：**思考的主体必须是你自己**。

在 Cogito 里，人和 AI 的分工被刻意设计成不对称的：

| 角色 | 负责什么 | 具体动作 |
|---|---|---|
| **你（思考者）** | 选题、定方向、判断对错 | 决定哪张卡要深入、哪张要发散、哪张要分支；编辑、推翻、重组任何卡片 |
| **AI（展开者）** | 把你指出的方向拆开、铺开 | 生成语义连贯、有信息增量的卡片草稿；给出分支建议；提取术语定义 |
| **你（终审者）** | 最后裁判 | AI 的输出只是草稿，每一张卡片都保留完整的人为编辑能力 |

为什么这样设计？因为 AI 最擅长的是「顺着一个方向展开」，最不擅长的是「判断哪个方向值得展开」。把前者交给 AI，把后者留给人——这不是美德，而是效率：**让每个人做自己最不可替代的事**。

## 功能详解：每一个功能解决什么痛点

<img src="https://cdn.jsdelivr.net/gh/waliean/cogito@main/assets/features.png" alt="Cogito — 三个核心结果" width="100%">

### 1. 卡片化知识树：让思考「长」起来而不是「流」走

**它是什么**：知识的最小单元是「卡片」（标题 + Markdown 正文 + 术语列表），卡片通过三种关系生成子卡：

| 生成模式 | 含义 | 场景 |
|---|---|---|
| **深入**（child） | 挑卡片中的某一个点，往下钻得更细 | 一个概念要挖到底时 |
| **发散**（divergent） | 从卡片出发，探索相邻和相关方向 | 思路需要拓宽时 |
| **分支**（branch） | 顺着卡片中的某条线索，分出新的支线 | 一条线索值得单独展开时 |

**解决了什么痛点**：痛点一（问完即弃）与痛点六（不可控制）。生成出来的不是「一段回答」，而是**一张独立的、可编辑的卡片**——你可以改标题、改内容、删掉重来、甚至把它挪到别的父节点下，而不会影响整棵树。已有子树在增量生成时**绝不会被重写**。

**技术亮点**：单卡内容有硬约束（标题 ≤40 字、正文 200~500 字 Markdown、术语 3~6 个并强制逐字出现在正文中），保证卡片「小而准」，树「密而清」；每张卡的 `parentId` 显式记录血缘关系，可完整回溯从根到叶的思考路径。

---

### 2. MindScape 思维导图：一图纵览，卡片/导图同源联动

**它是什么**：基于 @xyflow/react + dagre 确定性布局的思维导图视图。卡片列表与思维导图**共用同一份数据**，一键切换，双向联动：点击导图节点即打开对应卡片详情；在卡片列表增删改，导图实时同步。

**解决了什么痛点**：痛点五（碎片不成体系）。市面上「笔记工具」和「思维导图工具」是两套系统，数据不互通，导图画完就与笔记脱节。Cogito 里它们是一个东西的两种呈现。

**技术亮点**：
- dagre 确定性布局——同一棵树每次打开布局一致，不会「鬼抖」；
- MiniMap 小地图按卡片状态着色（草稿/处理中/完成/失败），上千节点也能一眼定位；
- 小地图可拖拽调大小、节点支持折叠子树，超大树的阅读效率可控；
- 纯前端 `dagreLayout(nodes, edges)` 纯函数设计，布局逻辑可单测、可替换。

---

### 3. AI 分支建议：面对空白，先给你三个方向

**它是什么**：在导图中选中一张卡片，点「分支建议」，AI 会分析这张卡的内容，给出 **3 条建议**——深入、发散、分支各一条，每条带标题和一句理由（如「建议深入：状态机与并发冲突——卡内提到 processing 状态未展开」）。你看完建议，决定采纳哪条、不采纳哪条；采纳即一键生成对应子卡。

**解决了什么痛点**：痛点二（主动权被夺走）与「空白画布焦虑」。很多人卡住不是因为不想想，而是面对一张卡不知道往哪拓展。这里 AI 的角色是**参谋**而不是**代笔**——建议只帮你降低「从哪下手」的启动成本，方向判断和最终决定权始终在你手里。

**技术亮点**：`POST /api/cards/:id/suggestions` 是**只读接口**，不修改任何卡片状态；建议数量/长度有硬校验（title ≤20 字、reason ≤40 字），不足 3 条自动重试一次；「采纳生成」复用与单卡生成完全相同的状态机与错误处理，行为一致可预期。

---

### 4. 一键生成完整图：一棵按钮长出一片森林，且绝不破坏已有成果

**它是什么**：工具栏「生成整树」，配置生成深度（1~3 层，默认 2）和每节点分支数（1~4，默认 3），对话框**实时预估将生成的卡片数**，确认后从每个根节点按广度优先逐层生成完整导图。

**解决了什么痛点**：痛点一与痛点五的规模化版本。手动一张张生成一座几十卡的导图，是几十分钟的重复劳动；而想用「一次性问答」获得整图，又完全不可控——预算、顺序、失败都不可知。一键生成把「铺一棵大树」从体力活变成一次配置。

**技术亮点**（这是本项目最「工程化」的功能之一）：
- **增量语义**：已有子卡的节点直接跳过，绝不重写现有子树——你的手工修改永远安全；
- **预算保护**：整树含已有卡最多 50 张，超限/无根卡/参数越界直接 400，杜绝失控烧钱；
- **部分失败收集**：某个节点 AI 失败不影响整棵树，失败清单（节点、错误码、原因）汇总在结果中一并返回，200 而不是整体报错；
- **动态超时**：`min(timeout × 预估调用数, 300s) + 30s`，按几何级数预估调用量，长任务不死等；
- 串行递归调用，避开 `E_CARD_BUSY` 并发冲突，语义与单卡生成完全一致。

---

### 5. 术语库 + 内置词典：把 AI 黑话翻译成人话

**它是什么**：三层递进的术语体系：

1. **自动高亮**：AI 生成卡片时强制提取 3~6 个术语并给出定义，正文中逐字高亮；
2. **悬停即释 / 点击联动**：鼠标悬停在术语上弹出定义，点击任意卡片里的术语，全局所有出现处同时高亮，术语库侧栏同步定位；
3. **内置 AI 编码词典**：随应用内置 62 条 AI 编程术语的汉化百科（模型 / Token / 上下文窗口 / MCP / Subagent……），正文中出现词典词条时以斜体/加粗/下划线样式独立区分，悬停即查；另有独立的「词典」视图可完整浏览，以及「词汇表」视图管理你**手动收藏**的术语（同名不同义自动分开展示并标注来源卡片，支持一键全选保存）。

**解决了什么痛点**：痛点三（黑话挡路），**尤其利好初学者**。陌生术语不再需要跳出上下文去搜索引擎，阅读密度骤降；而「同一术语在不同卡片中的不同定义」这种最容易混淆的情况，通过来源标注被显式暴露而不是被糊弄过去。

**技术亮点**：高亮采用**最长优先匹配**（`term.length` 降序，避免「上下文」吞掉「上下文窗口」）；Markdown 详情页用 TreeWalker 只包裹纯文本节点，**不触碰任何 HTML 结构**——高亮功能没有引入 XSS 面；词典数据由独立脚本从 `ai-coding-dictionary-zh` 仓库生成、可离线更新。

---

### 6. 文档导入（PDF / TXT）：长文一键变卡片树

**它是什么**：上传 PDF 或 TXT（≤10MB），后台自动完成 「文本提取 → AI 结构化摘要 → 自动生成根卡」的流水线：一张上传的论文，几分钟后变成一棵可从任意角度深入生长的知识树，根卡与原始文档（`sourceDocumentId`）保持血缘关系。处理进度 1.5 秒轮询，失败可一键「重新摘要」。

**解决了什么痛点**：痛点四（长文难啃）。摘要工具给的是「一段结论」，Cogito 给的是「一个起点」——摘要作为根卡，你可以立刻对它的任意一句展开深入/发散/分支，把「读完了」变成「读进去了」。

**技术亮点**：
- 上传校验是**成对的**：MIME 类型与扩展名必须一致（防 .pdf 伪装成 text/plain）；
- TXT 解码自动探测 UTF-8（含 BOM）失败后回退 GBK（iconv-lite），Windows 中文环境的老文件不再乱码；
- 扫描版（无文本层）PDF 明确报 `E_PDF_NO_TEXT` 而不是给出垃圾摘要；
- 摘要流水线串行排队（202 → 队列 → 提取 → AI 摘要 → 自动建根卡），避免并发打爆限流。

---

### 7. 文件夹工作区：把整个本地文件夹变成知识来源

**它是什么**：创建工作室时可以直接关联一个本地文件夹（桌面版弹系统文件夹选择器），应用内提供类 VS Code 的文件树浏览器：浏览层级、预览文本/Markdown/PDF、把选中文档一键导入为卡片树。

**解决了什么痛点**：痛点五（碎片散落）。资料稀疏地分布在本地各个目录时，逐个拖拽上传是纯体力活；为文件夹建一个工作室后，**文档浏览与导入呆在同一个界面里**，路径与血缘关系保持透明。

---

### 8. 全程溯源（aiMeta）：每张卡片都有「出生证明」

**它是什么**：每次 AI 调用（生成卡片、文档摘要、分支建议、整树生成）都会如实记录 `aiMeta`：**模型、输入 Token、输出 Token、耗时（ms）、是否重试过、失败时的错误码**，展示在卡片与文档详情中。

**解决了什么痛点**：痛点六（不可信、不可溯源）。「这次回答怎么这么贵？」「为什么和上次不一样？」「到底失败在哪个环节？」——不再靠猜，全部有据可查：Token 数让你看得见成本，错误码让你直达原因（429 限流 / 504 超时 / Key 无效），`retried` 字段告诉你结果是否经过重试，避免把「偶然性」误判为「规律」。

---

### 9. 本地优先与隐私：数据与 Key 只属于你

**它是什么**：全应用双机位本地化——

- **数据本机**：卡片、文档、设置全部存放在本地 JSON 文件（`backend/data/db.json`）与本地 `uploads/` 目录，不上传任何云端；
- **Key 本机**：API Key 只写进本地库；`GET /api/settings` **永不返回 Key 明文**——只暴露 `hasApiKey` 等非敏感配置，即没有任何接口路径会把你填的 Key 回传出去；
- **三级 Key 解析**：请求头 `X-API-Key` > 本地设置 > 环境变量 `DEEPSEEK_API_KEY` 三级回退，团队/脚本场景无需在界面里填 Key；
- **仓库安全**：`db.json` 与 `uploads/` 在 `.gitignore` 中，就算你把项目推上 GitHub 也不会把 Key 带出去。

**解决了什么痛点**：痛点七（隐私红线的代价）。对「保密资料别上云」的硬约束场景——企业内参、未发表的论文、个人研究笔记——这是**能用 AI**与**不能用 AI**的天壤之别；对普通用户，则省去了注册、登录、订阅的一整条数据交换路径。

---

### 10. 可靠性与容错：断电不丢数据，失败看得懂

**它是什么**：面向真实使用的工程化兜底：

| 风险 | 对策 |
|---|---|
| 断电 / 死机 / 程序被强杀 | 临时文件 + 写入后 JSON 校验 + 覆盖落盘的写入流程，配写队列串行化；异常数据自动备份为 `db.json.corrupted-{时间戳}.bak` 并重建空库，数据不静默损坏 |
| AI 服务抖动 | SDK 重试 3 次（带指数退避与 Retry-After），JSON 解析失败重试 1 次，卡片状态机 `draft → processing → done / failed` |
| 手滑重复点击生成 | `processing` 期间再次生成返回 409 `E_CARD_BUSY`，防重入 |
| 失败后不知道怎么继续 | `failed` 卡片一键重试；错误码全部映射为中文文案：429 提示降速、504 提示超时、缺 Key 直接引导去设置页 |

**解决了什么痛点**：痛点六（成本失控）的工程侧面。AI 应用最容易在「失败」的瞬间流失用户信任——这里的设计目标是**失败可恢复、错误可读、数据不丢**，把不确定性控制在用户能理解的范围内。

---

### 11. 桌面应用：安装即用，不需要懂 Node

**它是什么**：Electron 封装的 Windows 桌面版（NSIS 安装包 + 免安装便携版两种形态）。一个安装包搞定一切：应用内部自动拉起后端子进程、自动分配空闲端口、自动托管前端静态资源，系统托盘常驻，关窗口最小化、退出时自动清理后端。

**解决了什么痛点**：痛点「环境搭建」——没有桌面版，用 Cogito 需要 Node 22+、两个终端、手动管理端口，这对非开发者是劝退级别的门槛。桌面版让**安装 → 填 Key → 开始思考**变成三步，也是隐私承诺的最终落实（一切仍在本地）。

---

### 12. 中英双语（i18n）：界面一键切换，跟随系统

**它是什么**：应用界面（设置面板、卡片操作、错误提示，以及桌面版托盘菜单 / 窗口标题等主进程文案）支持中文 / English 双语，默认「跟随系统」；在「设置 → 语言」三选一，切换即时生效并持久化，下次启动保持。

**解决了什么痛点**：痛点「环境门槛」的延伸——语言偏好不应是安装时就必须做对的假设。让非中文用户也能零障碍上手，也让希望界面与文档语言一致的开发者省去折腾。

**技术亮点**：基于 `react-i18next` + `i18next`；语言偏好 `system | zh | en` 存于后端 `PublicSettings`（db.json）；Electron 主进程文案经 IPC 与渲染进程联动；错误码文案本地化但保留英文错误码契约；AI 编码词典与用户生成内容**刻意不翻译**。

## 快速开始

### 方式一：桌面版（推荐，非开发者友好）

1. 前往 [Releases 页面](https://github.com/waliean/cogito/releases)；
2. 下载 `Cogito Setup x.x.x.exe`（安装版，NSIS 向导）或便携版 zip（`win-unpacked.zip`，解压后直接运行 `Cogito.exe` 即可，无需安装；数据保存在 `Cogito.exe` 同级的 `data/` 目录，随文件夹整体迁移）；
3. 启动后打开右上角「设置」，填入你的 DeepSeek API Key，点「测试连接」：
   - Key 只保存在本机，界面与后端 API 均不回传明文；
   - 也可不填 Key，之后任何需要 AI 的操作都会引导你去设置。

### 方式二：开发模式（面向想改代码 / 二次开发的人）

```bash
npm install        # Node 22+（npm workspaces：shared + backend + frontend）
npm run dev        # 一键启动：后端 :3001 + 前端 :5173（Vite 自动代理 /api）
npm test           # 全部测试：后端 144 用例 + 前端 62 用例
npm run typecheck  # 全仓 TypeScript 类型检查
npm run dist:win   # 打包 Windows 安装版 + 便携版（输出到 release/）
```

### 首次使用三步

1. （可选）在设置中填入 API Key 并测试连接；
2. 创建一个工作区（或关联一个本地文件夹）；
3. 手动建一张卡 → 选中它 → 点「深入 / 发散 / 分支」生成子卡，或者直接上传一篇 PDF/TXT 让 AI 生成根卡。

## 典型工作流

以「读完一篇 AI 综述 PDF，并形成自己的知识体系」为例，完整走一遍：

1. **导入**：把 PDF 拖进工作区 → 后台提取文本 → AI 摘要生成根卡（标题、Markdown 摘要、术语自动提取）；
2. **通读**：正文里术语自动高亮，悬停即见定义——陌生概念当场消化，不用跳出去查；
3. **展开**：对根卡点「分支建议」，AI 给出深入/发散/分支各一条方向 → 采纳其中两条，进入深度阅读；
4. **分叉**：某条线索值得单独研究 → 用「分支」模式另起一条支线，卡片多而不乱；
5. **纵览**：切到 MindScape 视图，整棵树一张图；mini 图着色一眼看出哪些卡片还在草稿、哪些已完成；
6. **沉淀**：把高频术语收进词汇表（同名不同义自动分组、标注来源）；需要完整铺开时，用「生成整树」把花在重复操作上的时间省下来（增量语义保证你的手工修改不被覆盖）；
7. **复盘**：每张卡片的 aiMeta 让你知道整个探索花了多少 Token、哪一步失败过——成本与路径全程透明。

## 适用场景与边界

### 适合你，如果你……

- **学习者**：术语高亮 + 内置词典 + 卡片化拆解，是读书做笔记的降维工具（对 AI 编程初学者尤其友好）；
- **研究者 / 分析师**：长 PDF 论文 → 可生长的知识树，来源血缘可回溯；
- **写作者 / 思考者**：把「构思 → 展开 → 重组」变成显式的树状过程，避免灵感流失；
- **注重隐私的人**：企业内参、未发布稿件，全本机处理；
- **习惯让 AI 当外脑但拒绝被替代的人**：你思，它拓，分工明确。

### 不适合你，如果……

- **只想要一个更快的答案**：Cogito 刻意不替你做判断，它可能比聊天工具「慢」——这是设计使然；
- **需要图像/多模态输入**：当前仅支持 PDF/TXT 文本内容，扫描版 PDF 无文本层会明确报错（OCR 在路线图中）；
- **需要多人协作 / 云端同步**：当前定位是本地单机个人工具。

## 技术栈

| 层 | 技术 |
|---|---|
| 前端 | React 19 + TypeScript + Vite，zustand 状态管理 |
| 导图 | @xyflow/react（React Flow）+ dagre 确定性布局 |
| 后端 | Node.js + Express 5（全 ESM），JSON 文件存储 + 原子写 |
| AI | openai SDK（baseURL 指向 DeepSeek），JSON 模式、超时、重试、错误码映射 |
| 文档 | multer 上传校验 + pdf-parse 提取 + iconv-lite（UTF-8/GBK）解码 |
| 桌面 | Electron 43 + electron-builder（NSIS / 便携版） |
| 测试 | Vitest（后端 144 用例 + 前端 62 用例），supertest + jsdom |
| 仓库 | npm workspaces monorepo：`shared`（共享类型/常量）/ `backend` / `frontend` |

## 架构一览

```
[Electron 主进程 electron/main.cjs]
  ├─ 单实例锁；拉起后端子进程（随机端口）；解析 stdout 获得真实端口
  ├─ BrowserWindow 加载前端；系统托盘；退出时清理后端
  │
[backend  Express :3001（dev）/<随机端口>（desktop）]
  ├─ middleware: apiKey（X-API-Key 三级解析）→ error（统一错误码映射）
  ├─ routes: workspaces / cards(+generate+suggestions+generate-tree) / documents / terms / settings
  ├─ services: cardService / aiService / treeService / documentService / folderService / settingsService
  └─ storage: JSON 原子写 → backend/data/db.json    uploads/ → 原始文档
               │
[frontend  Vite :5173（dev）/<Express 静态托管>（desktop）]
  ├─ AppShell → 视图：cards（卡片树）| mindscape（导图）| glossary（词汇表）| dictionary（词典）
  ├─ stores（zustand）: workspace / card / document / settings / ui / term
  └─ TermText：全局术语高亮 + 悬停释义 + 词典词条独立样式
```

> 更深入的细节（数据 Schema、API 契约、状态机、Prompt 设计、ADR 记录）见 [docs/design.md](docs/design.md)；桌面封装细节见 [docs/packaging.md](docs/packaging.md)。

## 路线图

按 `docs/design.md` 中记录的已知边界与规划方向（非承诺）：

- **SSE 流式生成**：整树/长任务的流式进度与中途取消（设计中，当前为同步请求 + 动态超时）；
- **OCR 支持**：扫描版 PDF 的 B 方案（当前明确报 `E_PDF_NO_TEXT`）；
- **并发树生成**：当前整树为串行递归以规避 `E_CARD_BUSY`，后续可做受控并发加快大树生成；
- **数据导出**：知识树 / 词汇表的结构化导出（Markdown / JSON）。
